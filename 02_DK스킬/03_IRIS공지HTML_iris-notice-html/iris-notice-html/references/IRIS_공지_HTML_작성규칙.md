# 📢 IRIS 공지 HTML 작성 규칙 (공유용)

> IRIS(그룹웨어) 에디터에 **HTML로 공지를 올릴 때 반드시 지켜야 하는 기술적 조건**만 정리한 문서입니다.
> 아래 규칙을 지키지 않으면 ⓐ 미리보기에 **코드·태그가 본문으로 수집**되거나 ⓑ 붙여넣은 디자인이 **깨지거나 요소가 삭제**됩니다.
> 디자인 스타일·색·레이아웃은 각 팀 자유이며, 이 문서는 **"IRIS에서 안 깨지게 올리는 조건"** 만 다룹니다.
>
> 💡 **활용법:** 이 문서를 그대로 AI(Claude·ChatGPT 등)에 붙여넣고 "이 규칙을 지켜서 공지 HTML을 만들어줘"라고 요청하면 조건이 반영된 결과물을 받을 수 있습니다.

---

## 🧭 먼저 알아야 할 것 — IRIS 에디터는 붙여넣은 HTML을 "그대로 두지 않는다"

IRIS 에디터는 붙여넣은 HTML에 **두 가지 처리**를 합니다. 둘 다 방어해야 하며, 하나만 지키면 실패합니다.

| 레이어                | IRIS의 동작                                                              | 그대로 두면                                  | 대응                                                    |
| ------------------ | --------------------------------------------------------------------- | --------------------------------------- | ----------------------------------------------------- |
| **A. 수집(collect)** | 게시 시 **본문 앞쪽 텍스트를 긁어** 목록 미리보기·요약·알림 스니펫으로 사용                         | 배경 코드·장식 텍스트·태그가 먼저 잡혀 **미리보기가 코드로 오염** | 문서 **맨 앞에 숨김 요약 블록** (§4)                             |
| **B. 렌더(mangle)**  | 붙여넣은 스타일을 **강제 변형**(인라인 평탄화 · margin 0 주입 · line-height 강제 · 헤딩 특별취급) | 간격 붕괴 · 요소 겹침 · 글자 잘림 · 제목 깨짐           | **방어적 CSS**(prefix · 리셋 · div 제목 · `!important`) (§2) |

# 1. 문서 골격 — 이 순서로 작성

디자인은 **완전한 단일 HTML 문서 1개**로 작성합니다. 조각화·전체 인라인화는 필요 없습니다. IRIS는 `<style>` 블록의 시각 속성은 살려서 렌더합니다.

```
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <style> ... </style>
  </head>
  <body>
    <div … 숨김 요약 …>…</div>           ← §4 (맨 앞·필수)
    <div class="PREFIX-wrap"> … </div>   ← 디자인 본문 전체를 감싸는 래퍼
  </body>
</html>
```

- 결과물은 **`.html` 파일 하나**로 완결되어야 하며, 에디터에 통째로 붙여넣을 수 있어야 합니다.
- `PREFIX` = 공지마다 정하는 **고유한 짧은 접두사**(예: `hr0821-`, `safety-`, `noti03-`).

# 2. 에디터 강제 변형 대응 (렌더 방어)

## 2-0. IRIS가 실제로 하는 변형 (검증됨)

| IRIS가 하는 일 | 그대로 두면 생기는 문제 |
|---|---|
| `<style>`의 계산값을 **요소마다 인라인 style로 평탄화** (`font-size:18px` → 인라인 `13.5pt`) | 클래스로만 제어하려던 값이 인라인에 고정됨 |
| 모든 요소에 인라인 `margin-top:0; margin-bottom:0` **강제 주입** | margin 기반 간격이 0으로 붕괴 → **요소 겹침** |
| 모든 요소에 인라인 `line-height`(1.2 / 100% 등) **강제** | **글자가 위아래로 잘림** |
| `<h1>`~`<h6>` 헤딩 태그를 **특별 취급**(자체 heading box model) | 제목 크기·여백이 예측 불가로 깨짐 |
| `body{}` 선택자 **제거** | body에만 준 스타일이 사라짐 → 지면 스타일은 `.PREFIX-wrap`이 소유해야 함 |
| 붙여넣은 `<meta viewport>` **무시**(그룹웨어 고정폭 렌더) | `@media` 반응형이 발동하지 않을 수 있음 |

**반대로, IRIS가 건드리지 않는 것 (= 믿고 쓸 수 있는 것)**
- `<style>` 블록의 **시각 속성**: `background` · `border` · `border-radius` · `box-shadow` · `grid` · `flex` · `width/max-width` → 정상 렌더
- **인라인 `font-size`** 는 보존 / **`height`** 는 인라인으로 주입하지 않음
- **`!important`가 붙은 스타일시트 값은 인라인(비-important)을 이김** ← 방어의 핵심 지렛대

## ✅ 2-1. 모든 스타일에 고유 접두사(prefix)

- **모든 클래스·선택자·keyframe 이름**에 prefix를 붙입니다.
- 전체 디자인 본문을 **`.PREFIX-wrap` 하나로** 감쌉니다.
- ❌ prefix 없는 **전역 선택자 금지** (`body{}`, `p{}`, `.card{}` 등) — 그룹웨어 전체 스타일과 충돌하거나 제거됩니다.

## ✅ 2-2. 리셋 보일러플레이트 (필수)

`<style>` 맨 위에 그대로 넣고 `PREFIX`만 교체합니다.

```css
.PREFIX-wrap,
.PREFIX-wrap *,
.PREFIX-wrap *::before,
.PREFIX-wrap *::after{
  box-sizing:border-box !important;
  line-height:normal !important;
}
```

> **행간(`line-height`) 지정 시 반드시 `!important`.** 예: `line-height:1.6 !important;`
> 안 붙이면 IRIS가 덮어써 글자가 잘립니다. (색상·폰트·자간은 `!important` 없이도 OK)

## ✅ 2-3. 제목은 헤딩 태그 대신 `<div>`

- ❌ **`<h1>`~`<h6>` 사용 금지** — IRIS가 자체 heading box model로 처리해 크기·여백이 깨집니다.
- ✔️ 제목은 **`<div class="PREFIX-title" role="heading" aria-level="1">`** 로 작성 → 다른 요소와 동일하게 처리되고 접근성도 유지됩니다.
- 사용 가능한 태그: `<div>`·`<span>` 중심 + `<p>`·`<a>`·`<b>`·`<small>`·`<br>`·인라인 `<svg>`(+SMIL `<animate>`)
- 애매하면 **`<div>`로 감싸세요.**

## ✅ 2-4. 간격·여백 (요소 겹침 방지)

IRIS가 모든 요소에 인라인 `margin:0`을 주입하므로:

- **구조적 `margin`에는 `!important`** — 예: `.PREFIX-cards{ margin-top:18px !important; }`
- **가운데 정렬 `margin:0 auto` 에도 `!important`** — 안 붙이면 IRIS의 `margin:0`에 밀려 **좌측 정렬**됩니다.
- **제목 아래 여백은 부모가 소유** — `.PREFIX-head{ margin-bottom:40px !important }`, 제목 자체 margin은 0.
- ❌ **빈 div·`&nbsp;` 스페이서 금지** — IRIS가 height를 무력화해 간격이 사라집니다.
- 가능하면 `padding` · flex/grid `gap` 우선 사용 (IRIS가 인라인화하지 않는 속성).

## ✅ 2-5. 링크는 전부 새 창으로

공지 안의 **모든 `<a>` 는 예외 없이 새 탭으로** 엽니다. 읽는 사람이 게시판을 떠나면 공지의 나머지를 안 읽습니다.

```html
<a class="PREFIX-btn" href="…" target="_blank" rel="noopener noreferrer">신청하기</a>
```

- **`rel="noopener noreferrer"` 를 반드시 함께 붙입니다.** `target="_blank"` 만 쓰면 새 탭이 `window.opener` 로 원문서를 조작할 수 있습니다(reverse tabnabbing).
- **JS가 금지(§6)라 새 창을 여는 방법은 이것 하나뿐입니다.** `onclick="window.open()"` 류는 새니타이저가 제거합니다. 속성 방어라 JS 금지 규칙과 충돌하지 않습니다.
- **IRIS는 `target`·`rel` 속성을 보존합니다**(실측 확인) — 링크가 실제로 새 창에서 열리는 것을 게시분에서 확인했습니다.
- **검증**: `<a>` 개수 = `target` 개수 = `rel` 개수가 일치하는지 셉니다.

## ✅ 2-6. 불필요한 주석은 남기지 않기

**작업 메모·판단 이유는 붙여넣는 HTML에 남기지 않습니다.** 구역을 가르는 짧은 이름표만 남깁니다.

| | 예 | |
|---|---|---|
| ✅ **허용 — 섹션 구분 이름표** | `/* 마스트헤드 */` · `/* 코너 카드 */` · `/* 푸터 */` | 한 줄 · 구역 이름만 · **20자 이내** |
| ❌ **삭제 — 근거·메모형** | 「…때문에 이렇게 했다」 · 「7/31 실측」 · 「임시값」 · 「미확인」 · TODO | 이유·날짜·상태를 담은 서술 |

- **🔴 내부 판단이 그대로 노출됩니다.** 공지는 전 직원이 보는 문서이고, 소스는 누구나 열어볼 수 있습니다. 「이 값은 임시」·「○○ 때문에 우회」 같은 메모가 공지에 붙어 나가면 안 됩니다.
- **독자에게 주는 값도 없습니다.** 주석은 화면에 보이지 않고 미리보기로도 수집되지 않습니다(§4-2). 이름표는 **다음 사람이 소스를 고칠 때 위치를 찾는 용도**라서 남깁니다.
- **메모는 지우기 전에 옮깁니다.** 다시 필요한 내용이면 별도 작업 노트에 옮겨 적은 뒤 HTML에서 지웁니다.
- **AI로 만들었다면 특히 확인하세요.** AI는 CSS·HTML 곳곳에 설명 주석을 붙이는 경우가 많습니다. 요청할 때 "섹션 이름표 외 주석은 넣지 말 것"을 함께 적으면 편합니다.

# 3. 반응형 대응

## ✅ 3-1. "컨테이너 유동" 우선 — 뷰포트 `@media`에 의존 금지

IRIS가 viewport meta를 무시하기 때문에 `@media`가 발동하지 않을 수 있습니다. **핵심 반응은 미디어쿼리 없이** 컨테이너 폭 기반 유동 CSS로 구현합니다.

| 목적 | 방법 |
|---|---|
| 여러 열 그리드 자동 접힘 | `grid-template-columns:repeat(auto-fit, minmax(200px,1fr));` |
| 좁아지면 세로로 쌓기 | `display:flex; flex-wrap:wrap;` |
| 넘침 방지 | 모든 래퍼·이미지에 `max-width:100%;` |
| 넓은 표 | `min-width` 지정 + **가로 스크롤 래퍼**(`overflow-x:auto`)로 감싸기 |

- `@media`는 **꾸밈용(폴리시)으로만** 사용합니다. `!important` 없이, IRIS가 인라인화하지 않는 속성(grid / padding / background / border-radius / display / white-space)만 다룹니다.
- **검증법:** 뷰포트는 넓게 둔 채 **컨테이너만 좁혀서**(`document.querySelector('.PREFIX-wrap').style.width='360px'`) 그리드가 1열로 접히면 OK.

## ✅ 3-2. 모바일 지면 — 바깥 여백 제거

모바일(≤640px)에서는 래퍼의 바깥 여백을 없애 콘텐츠가 화면을 꽉 채우게 합니다. 작은 화면에서 좌우 여백을 내주면 본문 폭 손해가 큽니다. (웹·태블릿 >640px은 그대로)

```css
/* <style> 맨 뒤에 둡니다 */
@media(max-width:640px){
  .PREFIX-wrap{ padding:0; }
}
```

- **반드시 `<style>` 맨 뒤에.** `.PREFIX-wrap` 본 규칙과 특이도가 같아 **나중에 선언된 쪽이 이깁니다.** 앞에 두면 무효입니다.
- **`!important` 금지**(위 폴리시 조건). 카드·본문 **안쪽** 패딩은 그대로 둡니다 — 없애는 것은 바깥 여백뿐입니다.
- ⚠️ IRIS에서 `@media` 발동 여부는 환경에 따라 다를 수 있습니다. 안 걸리면 기존 모습이 남을 뿐 **깨지지는 않습니다.**

# 4. 내용 미리보기 — 맨 앞 「숨김 요약 블록」 (★필수)

IRIS는 게시 시 문서 **앞쪽 텍스트를 순서대로 긁어** 목록 미리보기·요약·알림 스니펫으로 씁니다.
따라서 **문서에서 가장 먼저 나오는 텍스트가 반드시 한글 공지 요약이어야** 코드·장식 텍스트가 아니라 우리 문장이 수집됩니다.

## ✅ 4-1. 위치 — `<body>`의 첫 번째 자식

`.PREFIX-wrap`(디자인 래퍼) **바깥**, 문서 최상단에 넣습니다.

```html
<body>
<!-- ▼ 미리보기 수집 유도용 숨김 요약(맨 앞 최우선·공백 제외 500자 이내). 화면 비노출·DOM 존재 → 스크랩 시 이 한글이 먼저 잡힘. -->
<div aria-label="공지 요약" style="position:absolute;left:-9999px;top:0;width:1px;height:1px;overflow:hidden;color:#111;font-size:14px;line-height:1.6;">
  [부서/그룹 사내공지] '○○○' 안내 — (한 줄 요약). (무엇을 알리는지 · 누구 대상 · 핵심 내용 2~3개). (신청/문의 방법). 문의: [담당자 연락처]
</div>
<div class="PREFIX-wrap">
  ... (디자인 본문) ...
</div>
</body>
```

## ✅ 4-2. 숨김 기법은 "오프스크린" — `display:none`·주석 금지

- ✔️ **오프스크린**: `position:absolute; left:-9999px; top:0; width:1px; height:1px; overflow:hidden;`
  → DOM에 살아있어 **수집은 되고**, 화면에는 보이지 않습니다.
- ❌ **`display:none` / `hidden` 속성 금지** — IRIS 새니타이저가 통째로 **제거**할 수 있어 미리보기에도 안 잡힙니다.
- ❌ **HTML 주석 `<!-- ... -->` 금지** — 주석은 텍스트로 **수집되지 않습니다.** 반드시 실제 `<div>` 요소여야 합니다.

## ✅ 4-3. 요약문은 "노출돼도 무해한 완성 문장"으로

- **공백 제외 500자 이내** 한글, 바로 게시 가능한 완성 문체.
  - 세는 법: `len(요약.replace(" ",""))`. 한글 문장은 공백이 약 1.29배 붙으므로 공백 제외 500자 ≈ 공백 포함 640자 안팎입니다.
  - **공백이 아니라 내용량을 기준으로 통일**한 것입니다. 공백 포함으로 재면 실제 정보량이 같아도 문장 구성에 따라 한도가 들쭉날쭉합니다.
- 담을 것: **무엇을**(공지 핵심) · **누구에게**(대상) · **왜/혜택** · **어떻게**(신청·문의) · **문의 채널**.
- 안전장치: 혹시 IRIS가 오프스크린 스타일을 벗겨 노출시키더라도 **맨 위에 멀쩡한 요약 문장이 보일 뿐**이라 손해가 없습니다.
- 개인정보·민감정보·금액은 넣지 않습니다.

# 5. 이미지 — `data:` URI 로만 넣습니다

**게시판에 붙여넣는 것은 본문 HTML 한 덩어리뿐입니다. 옆에 있던 이미지 파일은 따라가지 않습니다.**
로컬 브라우저에서 잘 보이던 `<img src="assets/photo.png">` 가 IRIS에서만 깨지는 이유가 이것입니다 — **파일이 잘못된 게 아니라 참조 방식이 잘못된 것**이라, 이미지를 새로 받아 바꿔 끼워도 그대로 깨집니다.

| | 예 | |
|---|---|---|
| ✅ **허용** | `src="data:image/jpeg;base64,/9j/4AAQ…"` | 문서 안에 그림이 통째로 들어가 단일 파일로 완결 |
| ❌ **금지** | `src="assets/photo.png"` · `src="./img/a.png"` · `src="https://…"` | **옆 폴더도, 외부 URL도** 게시 후 살아남지 않음 |

- **용량 기준: 권장 문서 전체 300KB대 · 상한 1MB 미만.** base64는 원본보다 약 1.33배로 불어나므로 원본 PNG를 그대로 넣으면 붙여넣기 부담이 큽니다. 실제 게시에 성공한 값은 **임베드 200KB 안팎(문서 전체 300KB대)** 이므로 이 안에 맞추는 것을 먼저 시도하고, 어떤 경우에도 **완성 `.html` 파일이 1MB를 넘지 않게** 합니다. 약 950KB 파일도 임시등록 후 정상 표시되는 것을 확인했지만(2026-10-21), **저장·로딩이 눈에 띄게 느려지므로** 300KB대를 권장값으로 둡니다. 원본이 크면 **컨테이너 폭의 1.5배 정도로 축소 + JPEG 품질 조절**로 맞춥니다.
  - macOS 예: `sips -Z 1200 -s format jpeg -s formatOptions 65 in.png --out out.jpg` (컨테이너 800px 기준)
- **AI로 생성한 이미지도 같은 기준입니다.** 생성 이미지는 크기가 크고 PNG로 나오는 경우가 많아 그대로 넣으면 1MB를 쉽게 넘습니다. 넣기 전에 **형식을 골라 줄입니다** — 어느 쪽이든 넣는 방식은 base64(`data:` URI) 하나이고, 고르는 것은 그 안의 이미지 형식입니다.
  - 사진·일러스트처럼 색이 많은 이미지 → **JPEG로 바꾸고 크기 축소**
  - 로고·아이콘처럼 색이 적거나 **투명 배경이 필요한** 이미지 → **PNG 유지 + 크기 축소**
  - 판단이 애매하면 **두 형식으로 모두 줄여 보고 더 작은 쪽**을 넣습니다. 선 · 면으로 그릴 수 있는 그래픽이면 이미지 대신 **인라인 SVG**(§5-1)가 더 가볍습니다.
- **CSS가 걷혀도 안 깨지게 `<img>` 에 직접 겁니다.** IRIS는 스타일을 인라인으로 평탄화하므로 클래스 CSS가 사라질 수 있고, 그때 `width` 속성값(예: 1200)이 그대로 먹어 컨테이너를 넘칩니다.
  ```html
  <img src="data:image/jpeg;base64,…" width="1200" height="800"
       style="display:block;width:100%;max-width:100%;height:auto;border:0;">
  ```
  `width`·`height` 속성은 종횡비 유지를 위해 남겨 둡니다.
- **검증**: `<style>` 을 전부 끈 상태로 렌더해 컨테이너를 넘지 않는지 보고, base64를 디코드해 원본과 바이트가 같은지(JPEG이면 `FFD8` 로 시작·`FFD9` 로 끝) 확인합니다.
- 사진이 여러 장이면 **한 장으로 합친 콜라주**가 낫습니다 — 태그 수·용량·행 높이 흔들림이 모두 줄어듭니다.

# 5-1. 로고·아이콘·도형은 인라인 SVG로 그려도 됩니다

**사진은 base64가 기본이고, 로고·아이콘처럼 선과 면으로 그릴 수 있는 것은 인라인 `<svg>`로 직접 그려 넣어도 됩니다.**

| 무엇 | 넣는 방법 | 이유 |
|---|---|---|
| 사진 · 실사 · 질감이 많은 그림 | **base64** (위 §5) | 점 하나하나가 정보라 코드로 다시 그릴 수 없음 |
| 로고 · 아이콘 · 도형 · 구분선 · 배지 · 단순 도식(단계·화살표) | **인라인 `<svg>`** 허용 | 용량이 작고, 확대해도 선명하고, 색을 바꾸기 쉽고, 움직임(SMIL)도 붙일 수 있음 |

- **본문에 `<svg>` 태그를 직접** 넣습니다. `<img src="logo.svg">`(경로)는 사진과 똑같이 깨집니다.
- **SVG 안에서도 외부를 부르지 않습니다** — `<image href="http…">`·외부 `<use href>`·`<foreignObject>`·`<script>`·`on…=` 속성 금지. 글자는 `<text font-family>` 대신 시스템 폰트 본문 텍스트로 두거나 `<path>` 윤곽선으로 그립니다.
- **`viewBox`를 반드시** 넣고, 크기는 태그에 직접 겁니다 — `style="display:block;width:100%;max-width:160px;height:auto;"`. CSS가 걷혀도 상자를 넘지 않습니다.
- SVG 안의 `id`(그라데이션·마스크 등)에도 **공지 prefix**를 붙입니다. 같은 화면의 다른 SVG와 이름이 겹치면 색이 바뀝니다.
- **뜻이 있는 그림**(로고·도식)은 `role="img"` + `aria-label="…"`(한글)을 붙이고, 장식은 `aria-hidden="true"`로 둡니다.
- **로고는 원본과 똑같아야** 합니다. 회사가 준 **공식 SVG 파일이 있으면 그 코드를** 넣습니다. AI가 PNG를 보고 새로 그린 SVG는 **원본과 나란히 놓고 모양·비율·색이 같을 때만** 쓰고, 조금이라도 다르면 **원본 PNG를 base64**로 넣습니다.

# 6. 금지 / 허용

**🚫 금지 (제거되거나 깨짐)**
- ❌ `<script>` · `onclick=` 등 **모든 JavaScript** — 새니타이저가 제거합니다.
- ❌ **외부 리소스** — CDN · 웹폰트(`@import` · Google Fonts) · 외부 이미지 URL · `<link>`
- ❌ **상대경로 이미지** — `src="assets/…"` · `./img/…` (§5). 붙여넣는 것은 본문 HTML 하나뿐이라 **옆 폴더는 따라가지 않습니다.**
- ❌ **prefix 없는 전역 선택자**
- ❌ **헤딩 태그(`<h1>`~`<h6>`)** · **빈 스페이서 div**
- ❌ `position:fixed` · 화면 밖 오버플로우 (단, §4 숨김 요약의 `position:absolute; left:-9999px` 는 예외적 허용)

**✅ 허용 (적극 활용)**
- ✔️ `<head>` 안 `<style>` 블록 → **클래스 기반**
- ✔️ CSS `@keyframes` · `transition` · `flex` · `grid`
- ✔️ **인라인 SVG** + SVG SMIL 애니메이션 (움직임이 필요하면 JS 대신 이것)
- ✔️ 이미지는 **base64 data URI**(§5) — 외부 URL·상대경로 ✕
- ✔️ 로고·아이콘·도형·단순 도식은 **인라인 `<svg>`** 로 직접 그려도 됨(§5-1) — 사진은 base64
- ✔️ 장식·아이콘은 **OS 기본 이모지**(📢 🤖 ✨)

**폰트 · 레이아웃 (기본 권장)**
- **폰트**: 시스템 폰트만. 한글 `-apple-system,'Apple SD Gothic Neo','Malgun Gothic',sans-serif` / 코드 `Consolas,'Courier New',monospace`. **웹폰트 금지.**
- **본문 폭**: 컨테이너 `max-width` 700~820px + 중앙 정렬.

# 7. 붙여넣기 전 검증

브라우저에서 HTML 파일을 열고 개발자도구 콘솔(F12)에 아래를 실행합니다.

### ① 미리보기 수집 검증 — 가장 먼저 잡히는 텍스트가 한글 요약인가

```js
document.body.innerText.replace(/\s+/g,' ').trim().slice(0,120)
// → "[…사내공지] '○○○' 안내 — …"  (한글 요약으로 시작하면 OK / 코드·영문으로 시작하면 실패)
```

### ② 렌더 변형 시뮬레이션 — IRIS의 강제 주입 흉내

```js
const wrap = document.querySelector('.PREFIX-wrap');
wrap.querySelectorAll('*').forEach(el=>{
  el.style.setProperty('margin-top','0px');
  el.style.setProperty('margin-bottom','0px');
  el.style.setProperty('line-height','1.2');   // font-size는 건드리지 말 것(IRIS가 보존)
});
```

실행 후에도 **요소가 겹치지 않고 간격이 유지**되면(구조 margin `!important` 덕분) IRIS에서도 안전합니다.

- [ ] `<script>`·JavaScript **0개** / 외부 리소스(CDN·웹폰트·외부 이미지·`<link>`) **0개**
- [ ] 모든 클래스·keyframe에 **고유 prefix** (전역 선택자 0개)
- [ ] `.PREFIX-wrap` **리셋 보일러플레이트** 포함
