이 폴더는 품의서 변환 프로그램을 고치는 AI작업실이다. 변환 프로그램 = 품의서 원문을 전자결재에 붙여넣을 HTML로 바꾸는 `프로그램\변환.py` · `프로그램\변환설정.json`.
사용자는 재경실 실무자다. 개발 용어 없이 짧은 업무 말로 답한다. 사용자는 결과 페이지(HTML 품의서 확인)의 건 번호와 줄번호로 고칠 곳을 말한다.

## 고칠 수 있는 것 · 없는 것

- 고치는 파일은 `프로그램\변환.py`와 `프로그램\변환설정.json` 둘뿐이다. 값만 바꾸면 되는 것은 `변환설정.json` (`_설명`에 각 값의 뜻), 거기서 안 되면 `변환.py`
- `프로그램\lib\`(pdf 읽기 부품)는 고치지 않는다. 고치면 「품의서 만들기」가 고친 프로그램을 쓰지 않는다
- 변환 프로그램은 파일을 읽고 HTML 글자만 돌려준다. 다음을 넣으면 「품의서 만들기」가 실행 전 검사에서 쓰지 않는다
  - `os` · `subprocess` · `socket` · `shutil` · `tempfile` · `ctypes` · `urllib` · `http` · `importlib` · `threading` 등 파일 · 다른 프로그램 · 인터넷을 다루는 모듈
  - 파일을 쓰는 `open(…, "w")` · `.write_text` · `.unlink` · `.mkdir` · `.rename` 등, `exec` · `eval` · `getattr` · `__import__`
- 이 폴더 밖(`02_도구` · `03_품의서 자료` · 상위 폴더 `01_품의서 넣기` · `02_HTML 품의서`)은 열거나 읽거나 실행하지 않는다. 품의서 원본과 실제 결과가 있다
- 품의서 내용(업체 · 금액 · 은행 · 사람 등)을 쓰거나 묻지 않는다. `○` · `A` · `0`은 가린 글자라 짐작해 채우지 않는다
- 시험 · 적용은 AI가 하지 않는다. 사용자가 「품의서 만들기」를 다시 실행하면 그 프로그램이 예전 품의서(시험 기준)로 시험한 뒤 새 버전으로 쓴다. 다른 품의서 모양이 바뀌어도 쓰고, 바뀐 것을 `시험 결과.md`로 알린다

```
01_품의서 AI작업실\         ← 이 폴더
├─ AGENTS.md              이 안내
├─ 품의서_작성규칙.md       요구사항 정본 (Guide 규칙 · HTML 규칙 · 점검표 · 추가 규칙)
├─ 품의서_HTML틀.html       HTML 모양 틀
├─ CHANGELOG.md           날짜 + 무엇을 바꿨는지 한 줄씩
├─ VERSION                지금 쓰는 변환 프로그램 버전 (품의서 만들기가 적는다)
├─ 프로그램\               변환.py · 변환설정.json  ← 고치는 곳 (lib\ 는 고치지 않는다)
├─ 샘플\건0000\            샘플입력.txt (양식만 남기고 같은 글자 수로 가린 품의서) · 샘플_줄번호.txt (결과 페이지와 같은 줄번호)
├─ 시험 결과.md            고친 프로그램을 쓰지 않았거나, 쓰면서 다른 품의서 모양이 바뀌었을 때만 생김 (가린 내용)
└─ 변환 오류.md            변환 프로그램이 어떤 파일을 바꾸다 멈췄을 때만 생김 (오류 종류 · 줄만)
```

## 대화의 첫 말에 따라

| 사용자가 말하는 것 | 할 일 |
|---|---|
| `건0003 9번 줄 …` 처럼 건 번호와 줄번호로 고칠 곳 | 아래 「고치기」 |
| `시험을 통과하지 못했대 …` | `시험 결과.md`를 읽고 까닭을 고친 뒤 「고치기」 3 · 4 |
| `다른 품의서 모양도 바뀌었대 …` | `시험 결과.md`의 달라진 줄을 보고, 바뀐 품의서는 고치기 전 모양이 나오도록 고친 규칙이 걸리는 조건을 좁힌다. 「고치기」 3 · 4 |
| `변환 오류가 났대 …` | `변환 오류.md`의 오류 종류 · 줄로 원인을 찾아 고친 뒤 「고치기」 3 · 4. 원본이 있어야 다시 일으킬 수 있는 오류는 원인 코드만 고친다 |
| `되돌려 줘` | 「`01_품의서` 폴더의 `이전 버전으로.bat`을 실행하세요. 바로 앞 버전으로 돌아가고 품의서를 다시 만듭니다.」라고 알려 준다 |
| 건 번호가 없음 | 「결과 페이지에서 고칠 품의서의 건 번호(예 : 건0003)와 줄번호를 알려 주세요.」 |

## 고치기

1. `샘플\[건 번호]\샘플_줄번호.txt`와 `샘플입력.txt`를 읽고, 사용자가 말한 줄을 `품의서_작성규칙.md` 「3. 점검표」와 비교한다. 샘플이 없으면 「품의서 만들기를 한 번 실행한 뒤 다시 말씀해 주세요」
2. 계획을 다시 묻지 말고 말한 곳만 고친다. 다른 품의서의 서식은 바뀌지 않게 규칙이 걸리는 조건을 좁게 잡는다 (예 : 원본에 그렇게 쓴 곳만)
3. 돌려 본다 : `..\python\python.exe 프로그램\변환.py "샘플\[건 번호]\샘플입력.txt"` → 고친 결과가 같은 줄번호로 화면에 나온다. `샘플_줄번호.txt`(고치기 전)와 비교해 말한 곳만 바뀌었는지 본다. 문법 확인 : `..\python\python.exe -m py_compile 프로그램\변환.py`
4. `CHANGELOG.md` 표에 날짜와 바꾼 것을 한 줄 더하고 알린다 : 무엇을 고쳤는지 줄번호로 한두 줄 + 「`품의서 만들기.bat`을 다시 실행하세요. 새 버전으로 만들고, 다른 품의서 모양도 바뀌었으면 결과 페이지 맨 위에 알려 줍니다.」

- 줄번호는 빈 줄 · 「아래」 줄 · 표도 한 줄로 센다. 한 줄 폭을 넘어 나눈 줄은 번호가 없다 (`|` 뒤에 이어진 줄)
- python 실행이 안 되면 코드만 고치고, 사용자에게 「품의서 만들기를 다시 실행하세요」라고 알린다
